# 设计说明

## 要解决的问题

一个人每天在飞书里被 @、被私聊几十次，大部分问题其实在本机就能查到答案：代码仓库、线上只读查询、自己以前说过的话、各项目的笔记。这个助手替你先把这一步做掉：查清楚、起草好，你只需要看一眼、点一下。

它要像一个跟了你很久的助理：认识来找你的人，知道你们的口径，记得你上次怎么回的；但没有你点头，什么都不往外发。

## 两个阶段

**起草**（你还没开口）

- 程序先零成本预取：发送人的人物卡、和消息相关的记忆、你近 90 天在这个会话说过的话、本地 agent 会话片段。能直接答的就不用再查。
- `claude -p` 在一个空的起草工作区里跑，`--dangerously-skip-permissions` 放开所有命令（白名单会把管道、`cd && …` 这类正常命令拦掉，白白浪费轮数），只用 `--disallowedTools` 禁掉发飞书消息的几条命令；提示词要求只查不改。最多 8 轮，到上限让它用已查到的收尾。
- 输出是结构化的 JSON：kind（答 / 要动手 / 要你定 / 不用回）、拟回复、查证过程、用到的记忆、要你批的操作（变成卡上的勾选框）、草稿里每个事实的依据。

**办事**（你在卡下说了话、或点了按钮）

- 你的原话交给起草时**同一个** Claude 会话（`--resume`），它有完整上下文。装了 Orca 就在 Orca 终端里跑，你能看、能插话；没有就后台跑，过程写日志。Orca 里的 claude 是交互式的，写完报告也不会自己退：每条结束的路（办完、超时、接口报错停了、报错重开）都关终端；助手或 Orca 重启过、关终端失败漏下的，每 10 分钟按进程扫一遍收掉——只认助手自己起的进程（`--resume <会话> --disallowedTools <禁发清单>` 原样匹配）、会话在卡片里、这会儿不在办、最后一句对话超过 30 分钟，你自己开的 claude 不会被碰。
- 以你的身份发消息只有一个出口：bin/fr。授权来自程序写进 `FR_CTX` 的你那句原话：
  - `--why` 必须是你原话里的片段，否定语境里的不算（「先不要发」里的「要发」）；
  - 收件人只能是原会话、原发送人，或你那句话里点了名的人和群；
  - 同一张卡、同一个人、同一句话只发一次；超时算「结果未知」，不重发；
  - 正文或附件里像 key 的，除非你原话明确让发（`--secret-ok` 也要引用原话），否则拒发。
- 要等别人回复再接着办：`fr wait` 记一个跟进，对方回了就叫醒原会话。你原话里要求的跟进，叫醒后可以在原话范围内接着办和发；Claude 自己挂的，叫醒后只能查、回复出卡等你确认。
- 办完写一份报告（做了什么、验证、在等什么、还要你定什么），变成一张新卡。

## 发之前的把关

- 草稿里答应了还没做的事（「我现在给你开一下，弄完告诉你」），或者没有验证就说「已经好了」：不发，卡上标红，换成「照发，事我自己办」。
- 发出去的话里有承诺的，记进承诺账本：卡上一直挂着「答应了还没做」和「去办答应的事」；说了「马上」的 30 分钟没做提醒一次；做完、验证过、也告诉了对方才关。

## 影子期

想让一部分消息不等你确认就发，但先不真的放手。Claude 给每条标「放手的话会怎么发」（直接发 / 倒计时 / 等你），程序再用硬规则往严里改：要拍板、要动手、草稿有占位、涉及钱、承诺时间、事实没查证、第一次找你的人、你的上级、外部会话，一律等你。只写在卡片「查证与依据」的第一行（不放卡头，免得像个开关），记下你最后怎么处理的，攒够了再决定放不放。

## 记忆

见 docs/MEMORY.md。几个取舍：
- 记忆是带来源、按天追加的 Markdown，人能直接读、能 git 回看；索引随时可以重建。
- 价格、权限、生产操作、对外承诺这几类必须你确认才算数。
- 矛盾不自动覆盖。动态状态只当线索。
- 你在原会话里亲自回的、撤回的，都是最好的反馈：每天拿来校正口吻和口径。

## 卡片

- 交互卡（Card 2.0）：拟发送是能直接改的输入框，点完或有了结果，卡片原地改成结果、按钮收起。
- 按钮回调走机器人应用的长连接（`lark-cli event consume card.action.trigger`），不需要公网回调地址；代价是一个应用同一时间只能有一个进程在收。
- 你也可以不点按钮，直接在卡片下（引用或话题里）说话；整句「发」「不」走快捷路径，其余原话都交给 Claude 理解。

## 安全边界

上面这些把关（起草禁发消息、fr 的原话授权、收件人范围、去重、key 拦截、发前拦承诺）防的是**误发和顺手发**：模型理解错了你的意思、草稿里顺手答应了还没做的事、把不该发的人也通知了一遍、把 key 贴进回复里。它们挡不住一个有意绕过的模型：

- 起草和办事都以 `--dangerously-skip-permissions` 运行（白名单会拦掉太多正常的查询命令），禁发消息靠 `--disallowedTools` 的命令匹配。把发送命令写进脚本文件再执行、换个调用方式，匹配不到。
- fr 的授权上下文是一个文件，路径在环境变量里；模型能读写本机文件，也就能伪造它，或者直接调 lark-cli。

所以：它和你本人有一样的权限，适合用在你信任的场景里（同事找你、你自己的群）。更强的隔离要靠进程和凭据层面：起草阶段换成只有只读权限的飞书应用、授权由助手进程在内存里核对（fr 通过本地 socket 问它），这些以后再做。

## 不做的事

- 不做中心服务、不共享机器人：每个人一台 Mac、一个自己的应用、一个自己的草稿群，数据都在本机。
- 目前只支持 Claude Code。别的 agent（DeepSeek Harness、Codex 等）以后再说：强制 JSON 输出、`--resume` 续会话、`--disallowedTools` 这几处要换成各家通用的做法。
- 不真的自动发（影子期只标注）。
