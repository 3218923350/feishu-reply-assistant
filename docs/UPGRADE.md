# 升级到 v0.2.0

从 v0.1.0 升上来大约 5 分钟。新功能**默认都不开**，升级完行为和以前基本一样；想用哪个，按下面打开。改完的东西都在 [CHANGELOG](../CHANGELOG.md)。

## 一、升级（必做）

```bash
cd <仓库目录>
git pull
./install.sh            # 重启常驻服务和每日任务；以前漏下的办事进程，新版本起来 10 分钟内会收掉
bin/fra doctor          # 看一遍有没有 ❌
```

`state.json`、记忆、配置都不用动，新版本自己会补上新字段。

**升级后马上能看到的变化**（不用配置）：

- 卡片按钮换了名字、换了位置（见下面「三、卡片怎么用」）。
- 群里的回复开话题了，话题里原发消息的人接着回会自动起草（不想要见下面的开关）。
- 起草不再限 12 轮，查清楚再交；难的问题会多花点时间和钱。想限住就在配置里写 `"max_turns": 20`。
- 起草期间你已经自己回了的，卡照样出、直接收起，可以在卡下接着让它办。
- 每天 06:30 记忆日报之后多一条「复盘」（`"daily_review": false` 关掉）。

## 二、按需打开的功能

都写在 `$FRA_HOME/config.json`（默认 `~/.feishu-reply-assistant/config.json`），改完重跑 `./install.sh`。每个键的说明在 README 的配置表和 `templates/config.example.json`。

### 1. 不等确认直接发

```json
"auto_send": true,
"auto_signature": "（{{name}}的助手代回）"
```

- 只发起草判定「直接发」、程序硬规则一条都没拦的（不涉及拍板、动手、钱、承诺时间，事实都查过，不是第一次找你的人、不是上级、不是外部会话）。发出去结尾带署名，卡片原地改成「已直接发」。
- 私聊里查了 5 分钟还没完的，先替你回一句「收到，我看一下」。改时间 `ack_after_minutes`，改说法 `ack_text`，`0` 不先回。群里不先回。
- 建议先开几天看看每天的复盘里「没等你确认就发的」那一节，再决定放不放宽。

### 2. 加入任务（要改代码的事，记下来你自己开会话干）

需要多授权一个飞书任务权限，再建一个任务清单（可选）：

```bash
lark-cli auth login --domain task      # 用户身份加 task:task:write
```

```json
"task_list_id": "<清单 guid>",
"task_agent": "claude"
```

`task_list_id`：飞书里打开清单，链接里 `guid=` 后面那串；不写就只指给你。`task_agent`：「开工」在 Orca 里起哪个 agent。

不配也能用：卡上标了「像是要开发」就会有「加入任务」按钮。「开工」需要开着 Orca，而且那个仓库在 Orca 里登记过。

### 3. 外部群发不出去时，操作飞书桌面客户端代发

```json
"messenger_url": "https://<你们租户>.feishu.cn/next/messenger/",
"desktop_send": true,
"desktop_model": null
```

`desktop_model`：兜底时 Codex 用的模型，`null` 用 Codex 自己的默认。

- 顺序：网页版飞书（Orca 内置浏览器里登录着）→ 飞书桌面客户端（先脚本，约 10 秒；不行再让 Codex 操作，几分钟）→ 都不行就把原文贴在卡下让你转发。
- 要求：飞书桌面客户端开着、登录着；Orca 有「辅助功能」权限（系统设置 → 隐私与安全性 → 辅助功能）；要 Codex 兜底就装好 `codex` 并能跑 `codex exec`。
- 代发时飞书会被切到前台，那个会话的未读会被清掉。话题里的消息和附件还发不了（附件会贴在卡下）。

### 4. 群里的话题

```json
"group_reply_in_thread": true,
"follow_thread_hours": 6
```

`group_reply_in_thread` 写 `false` 群里改用引用回复；`follow_thread_hours` 是话题里盯原发消息的人多久，`0` 不盯。

单张卡上不想盯：点卡上的「不用盯了」，或者在卡下回「不用盯了」。

### 5. 其他可调的

| 键 | 默认 | 说明 |
|---|---|---|
| `max_turns` | 不限 | 起草最多几轮工具调用 |
| `draft_timeout_minutes` | 40 | 起草最多查多久，到点用已查到的收尾 |
| `max_parallel` | 4 | 同时起草几条 |
| `daily_review` | true | 每天的复盘 |

## 三、卡片怎么用

按钮只有两种动词：**发** = 只以你的身份把卡上那句发出去，什么都不执行；**办** = 真的去执行（查线上、改配置、开权限），办的过程中可能以你身份发消息（只能发给原会话或你点名的人）。

| 卡片 | 按钮 | 以前叫 |
|---|---|---|
| 普通回复 | **发出这句** · 照我说的办 · 不回 | 发送 · 按我说的办 · 不发 |
| 要动手（开 key、加白…） | **去办** · 照我说的办 · 不回 | 按我说的办 · 只发这句 · 不发 |
| 有勾选项 | **办勾选项** · 先发这句 · 照我说的办 · 不回 | 同意所选 · 只回话 · 按我说的办 · 不发 |
| 话里答应了还没做的事被拦下 | **让它去办** · 照发，我自己办 | 我自己办，先发这句 |
| 发出去了、答应的事还没做（橙色） | **去办** · 我办好了 · 不办了 | 去做 |
| 像是要开发 | 多一个「加入任务」 | — |
| 群里发出去的 | 一行「👀 盯着话题」+「不用盯了」 | — |

几个容易踩的地方：

- 「照我说的办」要先在按钮下面的吩咐框里写一句；空着点不会办（以前空着点等于照卡上的话发出去）。
- 要动手的卡，草稿在「办完回他的话」框里，办完、验证过才发；把这一框清空再点「去办」，就是只办不发。
- 想接着跟某张卡聊：在卡下（引用或话题里）直接说话，和写吩咐一样。外部会话没发出去的卡，回「重发」再试；任何卡回「加任务 …」记进任务清单。

## 四、回滚

```bash
git checkout v0.1.0 && ./install.sh
```

v0.2.0 新加的状态字段 v0.1.0 会忽略，配置里新加的键也不影响。
