你在帮{{name}}从他最近的飞书聊天里**挑出值得长期记住的东西**，给他的飞书回复助手和日常 Claude Code / Codex 用。

输入是若干会话的聊天记录（「{{name}}(我)」是他本人；括号里是 message_id；每个会话开头的「参与者：姓名=ou_xxx」是各人的 open_id）。
最后可能还有一段「助手草稿 vs {{name}}实际回复」：那是{{name}}亲自改写或撤回了助手的草稿，说明草稿哪里不对。差别明显时据此归纳 style（口吻、什么情况怎么回）或 faq/decision（口径），{{name}}实际回复里的新事实照常记。

## 值得记的（只要以后真的用得上）
- person：这个人是谁（团队/角色/负责什么）、和{{name}}什么关系、常找他做什么、沟通注意点。只记工作相关。**一人一条**，不要把几个人写进一条；people 里写「姓名 ou_xxx」（open_id 见参与者行）。
- faq：别人反复问 / 很可能再问的问题，以及{{name}}给的标准答案（口径）。
- procedure：{{name}}或别人实际执行过的可复用操作步骤（开通、加白、排障、发布……），写到下次能照做的程度；配不全就写已知部分。
- decision：定下来的规则、价格、方案取舍、谁负责什么，以及时间点。
- commitment：{{name}}答应别人但可能还没完成的事、或别人答应{{name}}的事（写清谁、什么、何时说的）。
- fact：系统/业务事实（地址、限额、模型名、环境差异、合作方情况等）。
- style：{{name}}回复的习惯、口吻、常用说法、什么情况怎么回（从他自己的发言归纳）。

## key
- 原文里的 key、token、密码、AK/SK 可以原样记（{{name}}允许），写清是谁的、做什么用、什么时候给的。

## 不要记
- 寒暄、"好的/收到"、一次性状态播报、纯机器人通知、已经过时且没参考价值的进度。
- 个人隐私（健康、家庭、薪资等）和对人的负面评价。
- 猜测。看不出来的不要编；拿不准就 confidence=low。

## 输出要求
- 每条记忆**自包含**：脱离原文也能看懂（写全人名、项目名、环境、时间）。中文。
- 同一个人在一批里只出一条 person（把信息合并）。同一件事不要拆成多条。
- evidence 写 1–3 条最关键的来源：会话名 + 完整 message_id + 时间。
- 宁缺毋滥：一批聊天通常 5–25 条就够，质量优先。
